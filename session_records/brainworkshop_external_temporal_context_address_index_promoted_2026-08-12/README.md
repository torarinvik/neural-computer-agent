# Canonical external temporal context address-index promotion

The canonical context-conditioned temporal-route rung was rerun with
`ExternalTemporalAddressIndex` as the final replaceable address boundary.
The frozen controller and event encoder feed learned opaque event keys; the
outcome-only route learner selects mastered external files, and the index
materializes those opaque file positions without decoding a value basis.

Seed `17` at the promoted `512 + 512` update budget passed all `27/27` gates:
source and target mastery, route selection, old-file retention, wrong-file,
wrong-offset, missing-history, shuffled-feedback, reload, frozen-core,
zero-replay, exact and noisy index hits, unknown miss, index reload,
checksum-corruption rejection, and clear semantics. Accounting was `461,312`
unique verifier bits, `147,456` control bits, `49,408` logical lifetimes,
`1,024` optimizer updates, `520` route-memory updates, two opaque index writes,
and zero replayed examples.

This promotes canonical materialization and persistence of a learned opaque
address after route mastery. It does not promote address discovery, same-context
content search, compression, unrestricted growth, or general continual
learning; the two index writes are verifier-gated materialization, not a
learned index optimizer.
