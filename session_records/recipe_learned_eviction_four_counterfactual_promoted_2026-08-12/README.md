# Counterfactual four-candidate recipe maintenance — promoted bounded result

This is the next rung after the promoted two- and three-candidate results.
Each fresh lifetime contains four independent recursive recipe roots. A
generic capacity-pressure regime changes which depth rank must remain. The
policy sees only generic pressure context and permutation-safe structural
telemetry; it does not see the required-root identity, operations, digests,
task labels, or verifier rows.

The external maintenance layer evaluates every candidate eviction through the
authoritative copy-on-write verifier and trains on the resulting scalar
utility vector. This counterfactual credit estimator removes the variance that
made sampled three-candidate learning unstable. The controller and recipe
interpreter remain frozen, and no prior episode is replayed.

Across four seeds, transfer accuracy is `1.0000` on every seed and the stable
`0.90` threshold is reached at update `64` (`165,888` verifier bits). The
reward-shuffled null is exactly four-way chance (`0.7500`), corrupted features
average `0.7324`, candidate order is permuted, policy reload is exact, and
zero replay/controller updates hold. The scale-aware causal margin is `0.20`.

This promotes bounded counterfactual utility learning for four-candidate
external maintenance. It does not establish universal eviction economics,
semantic compression, unrestricted memory growth, or general continual
learning. The explicit cost is four verifier outcomes per maintenance lifetime;
the next rung is capacity growth and retention under repeated replacement.

Raw reports are `seed_*.json`; aggregate accounting is in
`report_summary.json` and `sample_efficiency_ledger.json`.

Run the rung with:

```text
uv run python experiments/recipe_expressibility/learned_recipe_eviction.py \
  --candidate-count 4 \
  --credit-mode counterfactual \
  --seed 73001 \
  --report-out /tmp/learned_recipe_eviction_four.json
```
