# Held-out primitive transfer — rejected

Four source primitives were acquired sequentially, then the shared external
register interpreter was frozen. A fifth unseen `rotate` primitive was
acquired using only a new opaque instruction code and fresh outcomes. Both
seeds mastered the source set and the new target.

Every retention, reward-shuffled, missing-evidence, exact-reload,
checksum-corruption, frozen-parent, and zero-replay control passed. Positive
transfer did not: seed `69316` tied fresh at `8,192` stable bits, while seed
`69317` required `24,576` versus `4,096` fresh.

Conclusion: the current learned operator supports reusable composition but
does not yet provide a transferable code-to-new-primitive computation prior.
That is the next architectural bottleneck.
