# Promoted: persistent cost-sensitive compression

Each seed ran one evolving route-memory store for 300 events. The store began
with two redundant pairs and mastered anchors, then received repeated
compression opportunities, important routes, unprotected distractors, growth
pressure, and a reversed schedule. The verifier assigned full utility to
compression, lower utility to admission/eviction, and `0.65` utility to
growth, making storage cost observable to the policy.

Across seeds `85901`–`85904`, every gate passed. Each stream committed exactly
two persistent compressions, grew 41–48 times, retained every mastered route
at every measured prefix and at final verification, and ended with stable
utility `0.8125`. Trained cumulative utility was `149.8`–`181.9`, versus
`0.0`–`3.8` for fresh controls. Each run used 300 unique utilities, 300
updates, zero replay, and a frozen controller.

This promotes persistent bounded cost-sensitive compression and retention. It
does not establish unrestricted growth, universal economic planning,
autonomous verifier design, or general continual learning.
