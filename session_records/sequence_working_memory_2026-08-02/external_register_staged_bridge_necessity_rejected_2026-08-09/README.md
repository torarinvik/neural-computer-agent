# Staged outcome-only bridge necessity diagnostic

This is a rejected alignment intervention, not a promoted capability.

The parent controller and source decoders remained frozen. A
capability-conditioned event bridge was first trained on valid source streams
using sampled scalar verifier outcomes. An optional second phase then trained
only the bridge on norm-matched unusable evidence while masking the controller
state. The purpose was to test the exported-session rule that acquisition must
precede necessity/protection pressure.

Results:

- Seed `69316`: source behavior degraded during late necessity updates and the
  transactional selector retained the earlier acquisition checkpoint.
- Seed `69317`: decoy behavior worsened during necessity updates, with source
  quality also declining on one primitive; the earlier checkpoint was retained.
- Source and target behavior gates passed at the bounded audit surface, but
  fresh target prefixes were incomplete, so positive sample-efficiency transfer
  was not evaluated as a promotion.

Conclusion: staged necessity is a safe candidate-selection rule, not the
missing representation-alignment mechanism. The canonical default remains the
acquisition-only bridge prior, and the next bottleneck is source-state/interface
geometry.
