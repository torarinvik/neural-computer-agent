# Opaque learned consolidation — 2026-08-06

Status: promoted narrow memory-side learned consolidation boundary.

The canonical `OpaqueConsolidationPolicy` was trained only from scalar rewrite
utility over controller-native keys and values. Its pair representation is
permutation-equivariant; it proposes a mechanical merge/keep rewrite, while an
immutable transaction and retention gate remain authoritative for adoption.
No raw modality, task label, correct action, or physical row identity entered
the policy features.

Across seeds 69316 and 69317, the learned policy selected a verifiable duplicate
pair on `100%` of 512 held-out banks, preserved candidate permutation, beat the
untrained and reward-shuffled controls, and dropped the synthetic bank from
eight rows to four through four accepted rewrites. Every rewrite passed fresh
retention outcomes; the source snapshot remained unchanged.

The audit is intentionally a memory-side mechanism test. It promotes learned
opaque rewrite selection and verifier-gated sequential compaction, not learned
byte compression, arbitrary program induction, unrestricted memory growth, or
general continual learning. The next pressure test must use independently
acquired executable artifacts and held-out sensory behavior rather than only
latent duplicate utility.
