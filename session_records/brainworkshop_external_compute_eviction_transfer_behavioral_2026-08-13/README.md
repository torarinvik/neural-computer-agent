# Behavioral artifact-signature transfer rejection

This directory preserves a matched fresh-learner audit of a behaviorally
grounded candidate signature for external-compute eviction. It is negative
evidence and is not a promotion record.

The policy no longer receives sampled parameter coordinates when
`candidate-signature=behavioral`. Each artifact is loaded into an isolated
physical slot and run on the same fixed sequences of standardized learned
event tensors and frozen controller intentions. The signature records the
shared interpreter's register, readout intention, and decoder-logit trace,
then applies one fixed projection to the policy's 32-wide candidate input.
The controller, event frontend, source artifacts, and executable files remain
frozen during transfer; the policy receives only fresh scalar verifier
outcomes and replay is zero.

Both seeds mastered all six source files and the held-out n-back-2 file at
`1.0000`, preserved held-out retention at `1.0000`, and passed frozen-boundary
and artifact-integrity controls. Seed 17 still gave inherited transfer
accuracy `0.0000` versus `1.0000` for the matched fresh policy. Seed 18 gave
`1.0000` for both inherited and fresh policies. The two-seed result therefore
does not establish reliable reusable eviction knowledge and remains rejected.

The signature is a valid architectural boundary improvement—it removes raw
weight coordinates—but the fixed two-step probe does not yet expose the
capability identity needed for reliable transfer. The next experiment should
use a richer leave-one-family-out functional probe set, measure signature
stability under equivalent artifact implementations, and retain the verifier
safety gate.
