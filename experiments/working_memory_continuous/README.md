# Continuous working-memory pressure test

This experiment family treats Brain Workshop-style working-memory skills as
controller–memory integration tests. The canonical production package owns
the controller growth boundary and external artifact store. The archived
controller remains only as a compatibility fixture for older learned
artifacts and for the shared clean-room task generator.

The first audit migrates two real learned span procedures into
`neural_computer.ExecutableArtifactMemory`, reloads the store in a fresh
instance, rehydrates each artifact on the common frozen parent, and checks:

- exact routed behavior versus the direct learned child;
- causal loss after zeroing only the loaded artifact;
- parent-controller bit identity;
- artifact hash rejection after corruption.

This is a persistence and executable-growth-state boundary result, not a
cold-start learning or general cognition claim.

## Frozen-controller acquisition

The next rung trains a zero-output successor slot from outcome-only working-
memory episodes while freezing the parent controller. The learned slot is
stored as tensor-only external growth state, reloaded through the canonical
`load_growth_artifact` boundary, and audited against the live child. Parent-
logit distillation on fresh inherited rehearsal streams is trainer-only and
exists to protect old behavior.

The complement primitive is the first replicated result: seed 61004 improved
from `42.19%` to `74.22%` and seed 61005 from `41.41%` to `75.00%`. Zeroing
the loaded artifact returned each run to its parent (`42.19%` and `41.41%`),
while rehydration matched the live child and retention on spans 4, 6, and 8
stayed within two points. Each run used 4,096 unique lifetimes and 20,480
unique verifier bits. The full record and ledger are in
`session_records/sequence_working_memory_2026-08-02/frozen_growth_complement_distill_2026-08-04/`.

The unprotected control reached the target but lost 3.91 points on span
eight; the same-budget success-only objective produced no target gain. The
current lesson is that external growth state is viable, but retention-safe
acquisition needs task-agnostic rehearsal protection. This remains a narrow
synthetic procedure result, not cold-start address discovery, arbitrary
program induction, exclusive reward attribution, or general cognition. The
reward-shuffled control still gained 7.03 points, far below the aligned
32--34-point gain, so reward correspondence is an open control rather than a
closed claim.

## Opaque address routing into executable growth (2026-08-04)

The next pressure test closes the missing memory-mediated step. A frozen
span-ten parent emits an opaque query after public sensory history and a
public operation cue. A replaceable memory-side router sees only that query,
random opaque candidate keys, attempted rows, and scalar verifier outcomes;
it does not receive a procedure name or a correct-row label. The selected
artifact is then rehydrated through the generic growth loader.

Two independent 512-update runs routed the mixed and complement procedures
at 100%, with reward-shuffled outcomes at the two-row chance baseline of 50%,
candidate-row permutation at 100%, and a raw cosine-key baseline at 50%.
Both selected artifacts were causal under zeroing, the complement wrong-row
control fell from 74.5/75.8% to 51.2/51.6%, and reload, frozen-core, and
corruption gates passed. The mixed procedure's wrong artifact performed as
well as the selected artifact, so that particular negative control is not
discriminative and is not claimed as evidence.

The accounting is deliberately explicit: each run generated 2,048 unique
logical lifetimes and 64 unique query/attempt verifier pairs, but sampled
32,768 verifier bits across 512 optimizer updates, including 32,704 replayed
samples. This is a replicated opaque-address routing result, not yet a claim
of general address discovery, arbitrary program induction, or broad
continuous learning. The full reports and ledger are in
`session_records/sequence_working_memory_2026-08-02/opaque_route_mixed_procedures_accounted_2026-08-04/`.

## Breakthrough: routing independently acquired procedures (2026-08-04)

Two independently acquired, same-schema artifacts now share one frozen
span-eight parent: span-ten `complement` and `complement_reverse` (reverse,
then complement). The parent started at 29.7% and 27.8%; frozen external
growth reached 76.4% and 63.8% after 512 updates, with +46.7 and +35.9 point
causal gains. Both acquisitions preserved spans 4/6/8, rehydrated exactly,
left the core bit-identical, and rejected corruption.

A replaceable memory-side router then selected the necessary artifact from
random opaque keys using only attempted rows and scalar outcomes. Across two
router seeds, routing was 100%, reward-shuffled routing 50%, candidate-row
permutation 100%, and cosine-only matching 50%. Selected execution reached
75.3--76.2% for complement and 63.6--63.9% for complement-reverse; wrong
artifacts fell to 26.9--30.0%, matching zeroed-growth controls. Every
wrong-address and causal-ablation gate passed.

This is the first narrow end-to-end evidence for the CPU/filesystem analogy:
external memory can store multiple independently acquired executable states,
and opaque outcome-trained addressing can retrieve the state required by the
current working-memory computation while the controller remains frozen. It
does not establish arbitrary program induction, cold-start general address
discovery, or broad intelligence. Forward span-ten and span-twelve rotate
acquisition controls were rejected because they produced no causal gain. Full
reports and accounting are in
`session_records/sequence_working_memory_2026-08-02/opaque_route_acquired_complement_bank_512_2026-08-04/`.

## Online bank growth and cross-procedure transfer (2026-08-04)

The artifact store now passes an online lifecycle audit: write one artifact,
evict its hot cache, cold-reload it, append a second artifact into a free row,
reload the bank, compact it, reload the compacted bank, and reject deliberate
corruption. Tensor payloads, SHA-256 hashes, and opaque keys remain exact
through every transition. The record is in
`session_records/sequence_working_memory_2026-08-02/online_artifact_growth_fixed_2026-08-04/`.

A three-row routing stress test also revealed an important boundary: a third
`complement_rotate` artifact transferred almost perfectly to the complement
procedure, and the complement artifact transferred back. Routing itself was
100% with the expected 1/3 shuffled and cosine controls, but the full
wrong-address gate failed. This is retained as evidence of shared learned
subroutines, not promoted as a third independent procedure. The next bank
experiment should require either an orthogonal computation or explicitly
measure beneficial transfer instead of treating all cross-artifact competence
as an error.

The transfer-aware three-row audit now passes as a compositional diagnostic.
All three procedures have at least one causal artifact, the selected artifact
is within five points of the best available artifact for every procedure, and
off-diagonal transfer is replicated for complement ↔ complement-rotate. The
strict independence gate remains false by design. This records a stronger
long-term memory model: artifacts may be reusable factors, not only isolated
monolithic programs. See
`session_records/sequence_working_memory_2026-08-02/opaque_route_acquired_three_procedure_compositional_2026-08-04/`.

The next orthogonal candidate, span-ten `global_parity`, was rejected at the
128-update diagnostic rung: target gain was effectively zero and the growth
ablation was not causal. It was not promoted or scaled. This keeps the
compositional result honest and identifies global aggregation as a separate
credit-assignment bottleneck.

## Replicated online append-to-route growth (2026-08-04)

The strongest current result is now online rather than static: the complement
artifact is written first, its behavior is measured, and a new
complement-reverse artifact is appended afterward. Across two seeds, the old
skill remained exactly unchanged, both rows routed at 100%, reward-shuffled
routing stayed at 50%, and selected execution remained 75.9--77.7% for
complement and 63.6--64.5% for complement-reverse. Wrong-address and zeroed
controls stayed near 27--30%, with frozen-core and corruption gates passing.
The full record is in
`session_records/sequence_working_memory_2026-08-02/online_routed_growth_2026-08-04/`.

## Multi-artifact execution composition (2026-08-04)

The top-k memory boundary now has an end-to-end execution audit. Two verified
artifacts were promoted together, remapped into disjoint generic growth slots,
and executed by one frozen controller. The composed model retained both
procedures across two seeds: complement stayed at `70.2%` versus `70.2%` in its
isolated slot, and complement-reverse stayed at `59.3%` versus `59.3%`; the
replica was `70.8%` versus `71.0%` and `58.9%` versus `58.9%`. Blank insertion
was bit-exact, both namespaces were distinct, and the frozen-core digest was
unchanged. This promotes reusable multi-artifact execution, not arbitrary
sequential program algebra. See
`session_records/sequence_working_memory_2026-08-02/multi_artifact_growth_composition_2026-08-04/`.

The next orthogonal candidate, adjacent-XOR, was rejected at the 128-update
diagnostic rung: target gain was `-0.625` points and the growth ablation was
not causal. It was not promoted or scaled. See
`session_records/sequence_working_memory_2026-08-02/frozen_growth_span10_adjacent_xor_128_2026-08-04/`.

## Genuine sequential factor composition (2026-08-04)

The producer→consumer ABI now passes a stronger pressure test. A promoted
span-ten complement artifact feeds a prior-only consumer whose input is only
the producer's learned register; the consumer also has a generic recurrent
register for temporal accumulation. On verifier-private span-twelve global
parity, the composed controller reached `99.09%` and an independent seed
reached `89.58%`; the aligned runs therefore span `89.58%`–`100%`, while
parent, producer-only, and consumer-only controls stayed at chance. Zeroing
either the producer register or the prior read returned to chance, and the
frozen-core, missing-evidence, reset, and reward-shuffled controls passed. This is the first
promoted evidence that external learned factors can form a new sequence-level
computation rather than merely coexist. It remains a narrow producer→consumer
ABI result, not arbitrary program algebra or general cognition. See
`session_records/sequence_working_memory_2026-08-02/prior_only_consumer_global_parity_span12_128_2026-08-04/`.

## Canonical controller growth-register pressure test (2026-08-04)

The same pressure test now runs through `src/neural_computer/`, rather than
the archived controller. A fresh canonical parent first learns span-three
forward reproduction. Its controller, frontend, and decoder are then frozen;
only two generic growth slots are trained outcome-only. Slot zero is a
producer artifact, and slot one is a recurrent prior-only consumer whose
input width is exactly the producer register width. Both artifacts are
persisted, reloaded, and remapped through `ExecutableArtifactMemory` and
`load_growth_artifact`.

Two independent 640-update runs passed all narrow gates. The composed score
was `85.94%` and `98.18%`, versus parent scores of `50.52%` and `42.71%`.
Producer-zeroed controls fell to `51.56%` and `37.24%`; prior-read ablations
fell to `46.61%` and `50.78%`; blank-sequence controls were `50%` in both
runs; reward-shuffled acquisition scored `49.22%` and `19.27%`. Artifact
reloads were exact and the shared controller digest remained unchanged.
The consumer-only replica scored `25%`; this is accepted as a no-bypass
control because it does not exceed its parent, rather than being forced to
land symmetrically around chance.

This promotes a narrow canonical producer-register → prior-only-consumer
working-memory mechanism. It does not establish arbitrary program induction,
long-span mastery, natural language, or general cognition. The harness is
`canonical_growth_pressure_test.py`; the full reports and accounting are in
`session_records/sequence_working_memory_2026-08-02/canonical_growth_pressure_consumer_long_2026-08-04/`.

## No-replay retention through executable capability files (2026-08-04)

The first shared-parameter curriculum established the failure mode: span 4
reached `84.4%`, but later updates reduced span 2 by `12.5` points and span 3
by `8.3` points. A summed append-only slot improved span-2 retention but still
allowed later slots to interfere, so it was rejected as the retention
mechanism.

The promoted solution isolates each learned capability. A span-2 parent is
trained once; span-3 and span-4 are independently acquired in generic growth
slots over the frozen parent, persisted as opaque executable artifacts, and
selected by an external context router. Later learning never updates earlier
artifacts and uses zero replayed examples. The router uses only the opaque
controller context and event-window occupancy, not a span label or raw frame.

Two prefix-audited seeds passed: route accuracy was `100%` for all spans;
selected span-2 and span-3 accuracy was `100%` in both; span-4 was `87.5%`
and `90.625%`. Span 4 first remained above the `80%` threshold at `12,288`
stable verifier bits in both runs. Blank controls were `50.0--51.2%`, the
frozen parent core was bit-identical, and `replayed_examples` was `0`.

This is the first replicated no-replay retention result, but its boundary is
important: it demonstrates frozen-core external capability files and routing,
not shared-weight SGD that magically avoids forgetting. General address
discovery, arbitrary program induction, and transfer to natural modalities
remain open. Reports, ledgers, and artifact stores are in
`session_records/sequence_working_memory_2026-08-02/canonical_no_replay_artifact_bank_512_2026-08-04/`
and its replication directory.

## Learned opaque address discovery (2026-08-04)

The occupancy route was then removed. Capability files were assigned random
opaque keys and a factorized query/key router learned which file to attempt
from fresh scalar attempted-row outcomes. The router saw only the canonical
controller hidden query and candidate keys; no span label, occupancy feature,
or correct unattempted row was supplied.

Two accepted seeds reached `100%` learned routing and `100%` candidate-row
permutation accuracy. Reward-shuffled routing stayed at three-way chance
(`33.3%`). Selected span-4 execution reached `86.7%` and `87.1%`, while spans
2 and 3 remained at or above `97.9%`. Replayed examples were `0` for both
capability and route training; stable span-4 acquisition required `16,384`
and `12,288` verifier bits. The factorized router is now the preferred
memory-side address policy; the older pairwise router remains available for
compatibility.

This closes the narrow hand-shaped routing bottleneck, not the general address
problem. The router still needs substantial fresh verifier evidence, and
arbitrary context-independent program discovery, route transfer across new
modalities, and online router retention under an expanding bank remain open.
Reports and ledgers are in
`session_records/sequence_working_memory_2026-08-02/canonical_no_replay_learned_route_factorized_2048_2026-08-04/`
and its replication directory.

## Counterfactual credit for opaque route decisions (2026-08-04)

The next credit-assignment bottleneck was isolated without changing the
controller or memory ABI. A trainer now pairs two distinct attempted artifact
rows inside the same fresh hidden world and uses only the difference between
their scalar verifier outcomes. For multi-row routing, the paired signal is a
bounded preference loss; binary write decisions use the corresponding paired
policy-gradient loss. Candidate identities, correct rows, and intervention
metadata remain trainer-private.

At the matched 512-update parent rung, route accuracy improved from chance at
512 paired updates to `70.8%`, then `83.3%` at 1,024 paired updates, and
reached `100%` at 2,048 paired updates. The accepted primary seed had `100%`
candidate permutation accuracy and `33.3%` shuffled-outcome accuracy; an
independent seed replicated `100%/100%` routing/permutation with `35.9%`
shuffled accuracy. Selected execution retained spans 2/3 at
`100%/95.3%` and `100%/97.9%`, with span 4 at `88.7%/87.1%`. Each accepted
run used zero replayed examples and `131,072` route verifier bits across
`65,536` paired counterfactual worlds.

This promotes the narrow counterfactual credit protocol as trainer
infrastructure and a route-acquisition mechanism, not general credit
assignment. The route still needs substantial fresh evidence, and credit for
multiple interacting writes, actions, and newly created computations remains
open. Reports and ledgers are in
`session_records/sequence_working_memory_2026-08-02/canonical_counterfactual_route_credit_logistic_2048_2026-08-04/`
and its replication directory; the 512- and 1,024-update rejected rungs are
retained alongside them.
